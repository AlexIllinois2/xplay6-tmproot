## §720 授权表丢失根因修复：`FileNotFoundException` 在 EACCES 时把"读不了"折叠成"空名单"

机主原话：「app 记不住已授权应用 老是丢」。

### 根因
`Chain.readGrantTokensOrNull`（Chain.java）的 catch 分支把 `java.io.FileNotFoundException`
直接当成"文件不存在 → 返回空表"。但 Java 在 **EACCES（存在、无读权限）时抛的也是
FileNotFoundException** —— root 侧工具（verify_approot.sh 走 daemon 写、grantsh 实验）恰好会
把 grants.txt 写成 0600 root:root（grants_rule_test 里的已测形态）。于是：

1. 所有"读不了就拒写"的保险（selfGrant / setShellGrant / saveSelection 都盯 `null`）**全部失效**
   —— 它们等的是 null，拿到的却是空表；
2. `listApps` 同样把 null 折叠成空 → 全部应用显示为未授权（机主看到的"授权丢了"）；
3. `checked` 镜像被清空后，用户随手勾任何一个应用，`saveSelection` 就按这份空镜像重写整表
   —— **真·整表清除**，只剩管理端自己（和 shell，如果 2000 恰好被保留）。

### 改动（Chain.java）
- `readGrantTokensOrNull`：区分"不在"（空表）与"在而读不了"（返回 null + lastGrantsError）。
  这一行补丁是整个修复的核心，所有拒写保险立刻恢复效力。
- 新增 `repairGrantsReadable(ctx, log)`：名单在但读不了时，借 root 通道
  `chown <me>:<me> + chmod 600` 把所有权还给本 app。**只修属主，一个字节内容都不改。**
- `selfGrant`：原"读不了就跳过"分支先试 `repairGrantsReadable`，修回则继续正常 reseal；
  修不回才维持拒写（老规矩不变）。
- `listApps`：读得 null 时先修一次再重读；修不回仍按空显示，但 saveSelection 此刻会拒绝
  按镜像重写，显示错误不会顺着下一次点击变成真丢。

## §721 「隐藏开发模式警告」开关与 watcher 运行态脱钩：显示开但不生效

机主原话：「设置项 碰到过显示的开启了隐藏开发模式警告项 还是没用 手动切换了一次开关才生效的」。

### 根因
开关存的是"**要**"（files/devwarn），watcher 是"**在**"（root 侧 app_process 进程）。devwarn
文件缺省为开，UI 只看文件就显示 ON；而 watcher 只有两处会被拉起——开关本身、提权成功后的
`Chain.run`。重启后等提权、watcher 死掉、或提权一直没成功的窗口里，UI 显示开、黄条照样回来。
用户手动切一次开关 = 手动跑了一次 `applyDevWarnChoice`，所以"切一下才生效"。

### 改动（Main.java）
- `applyStatus`：每次确认 root 可用（首页 status 探测）且存储选择为开时，后台补拉一次
  `applyDevWarnChoice`。幂等：DevWarn 的抽象 socket 单实例锁让重复拉起者自己退出；
  已活着只是白花一次 shell。选择为关时不做任何事。
