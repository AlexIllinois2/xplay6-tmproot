## §718 设置页加「ADB root 权限」开关：uid 2000 的增删从「应用授权」里翻出来，变成一行开关

机主原话：「设置里像其他root管理器一样加个给adb root权限的开关, 这样就不用麻烦的去系统应用里搜shell给权限了」。
现状量了一遍：机主今早 08:27 就是走的那条麻烦路——授权名单里已经有 2000（`cat grants.txt` 现读：
`2000 10137 10132 10133 10134`），是手动在「应用授权」页开「显示系统应用」搜 shell 打勾打进去的。
本轮把这条路径缩成设置页第一行开关。

### 改动面（3 个文件，没有动任何原生件）
- `tools/apk/src/com/xplay6/temproot/Chain.java`：
  - 新增 `SHELL_UID = 2000`、`shellGranted(ctx)`、`setShellGrant(ctx, on)`。**没有第二份真相**：
    开关状态从授权名单现读，不另存偏好文件——设置页开关和「应用授权」页里 com.android.shell 那一行
    永远是同一枚 uid 的两种看法，结构上不可能对不一致。
  - `setShellGrant` 沿用 selfGrant 的拒写规矩：名单读不到（root-owned 0600 的恢复路径形状）就
    **拒写并留 `lastGrantsError`**，绝不把看不到的名单当空名单重写（ledger 670/676 两次事故的同一条教训）；
    管理端自己的 uid 每次都带着，否则下次在列表里勾任何应用都存不下。
  - `saveSelection` 增补：落盘时若名单里已有 2000 且本次勾选项没含它，就保留它。理由是个真实的竞态——
    设置页开关写名单后 `refresh()` 是异步的，在刷新完成前点列表里任何一行，`checked` 的旧像会把 2000
    覆写掉。保留规则只认"名单里现在有"，而把 shell 行本身点掉走 `setShellGrant(false)` 显式摘除，
    所以这条补丁永远不会压过一次真正的撤销。
- `tools/apk/src/com/xplay6/temproot/Main.java`：
  - 「授权与安全」卡片第一行就是「ADB root 权限 / 授权 uid 2000：电脑上 adb shell 后 su 即得 root」，
    带 52x32 自绘 Toggle，与今早那批开关（USB模拟点击/隐藏开发模式警告/全局Hi-Fi）同一式样。
  - `toggleAdbRoot()`：工作线程里 `setShellGrant`，回 UI 后按落盘结果摆开关、写日志、toast、
    `refresh()` 让列表那一行说真话。撤销/授予都是**即时的**——sud.c `uid_allowed()` 与 relayd.c
    `allowed()` 都是每请求重读名单，不用重启任何进程。
  - `toggle(Entry)` 对 uid 2000 转派 `toggleAdbRoot`（目标态照该行当时显示的样子取，用户看到什么点的就是什么）；
    两处 UI 改完名单的地方（`revokeAll`、`showPage(PAGE_SETTINGS)`）都会重新同步开关。
- `tools/apk/AndroidManifest.xml`：versionCode 58→59 / versionName 1.9.39→1.9.40。
- `.gitignore`：加 `fw/`（本机符号链接到工作区根的三枚内核镜像，门禁要用，不入库）。
